## 利用場面と未確認事項

ユーザーが頻繁に行う操作は「付箋に保存したパスワード → ターミナル／ブラウザ」と「ロックしたメモからコピー → ターミナル」です。パスワード管理アプリへの漏洩不安があります。
実際の秘密は取得していません。端末の秘密入力プロンプトかシェルのコマンド行か、ブラウザの正規ログイン欄か別の欄か、履歴ツール・同期の有無、メモの具体的な認証方法は未確認です。生体認証によるメモ解除をSSOと同一視しません。

## 合成ダミーによる机上シミュレーション

一般パスワード用の仮の文字列を`DUMMY-PASSWORD-ONLY-7!`、既存検知対象を`AKIA0000000000000000`とします。どちらも認証情報を発行したものではありません。
下記は仮定した時系列で、OSの実測結果ではありません。通常文への切替や自動消去がない条件です。

| 時点・操作 | 一般ダミーパスワード | AWS形式ダミー |
| --- | --- | --- |
| t=0 コピー | 現行DetectorのAWS・秘密鍵条件には一致しない | AWS形式に一致する |
| t=2秒 正しい入力欄へ貼り付け | 貼り付けの成否・宛先をveil-clipは観察しない | 同左 |
| 検知から5秒後 | この内容には期限を設定しない | 再読取で一致すれば通知。消去しない |
| t=30秒 別の欄へ貼り付けようとする | ポーリングと端末通知に阻止機能はない | 同左。通知があっても誤貼付を止めない |
| コピー元の付箋・メモ | veil-clipでは元の保存内容を変更しない | 同左 |

これは`src/detector.rs`、Observeのみの`src/monitor.rs`、読取専用の`src/clipboard.rs`から導いた予測です。一般ダミーが除外されることは、すべてのパスワードを除外するという意味ではありません。偶然AWS形式などを含めば一致します。
同じ文字列がパスワードにも普通の文章にも使われるため、本文だけの判定から用途を確実に識別できません。文字数・文字種などの推測を足しても、誤検知と検知漏れの問題は残ります。

## 既存手段と役割

- ロックしたメモ：Appleはエンドツーエンド暗号化とパスワード／生体認証による閲覧を説明しています。これは保存内容の仕組みであり、コピー後の別アプリの入力まで保護する証拠ではありません。[Apple Platform Security](https://support.apple.com/guide/security/secure-features-in-the-notes-app-sec1782bcab1/web)
- Appleの「パスワード」：対応するサイト・アプリへの自動入力があります。その場面で手動コピーを減らす候補です。任意のターミナル用途すべてへの対応や、コピーした内容の自動消去はこの資料から保証しません。[Appleの案内](https://support.apple.com/en-us/120758)
- 1Password：Macのコピー設定に90秒後の消去が案内されています。1Passwordからコピーする経路の機能で、付箋やメモからのコピーを一律に消すとは扱いません。既に読み取られた内容や履歴全体の消去も保証しません。[コピー設定](https://support.1password.com/copy-passwords/)
- 1Password Universal Autofill：Macのアプリ・ブラウザと、Terminal等のsudoパスワード入力が案内されています。Accessibility権限が必要です。使用中の入力先での動作は未確認です。[自動入力](https://support.1password.com/mac-universal-autofill/)
- 1Passwordの保存：公式設計はエンドツーエンド暗号化と、アカウントパスワードに組み合わせるSecret Keyを説明しています。これはベンダーの設計資料であり、無事故・無漏洩の証明ではありません。[セキュリティモデル](https://support.1password.com/1password-security/)

付箋が画面に見えている間の露出、コピー後の誤貼付、保存先の侵害、入力先の偽装、端末侵害は別の問題です。ターミナルのコマンド行に秘密を入れる場合と、秘密入力プロンプトへの入力も区別します。履歴等への残留はプログラム・設定次第で、この評価では実環境を確認していません。

## 判断と終了条件

**この利用場面に対する現行veil-clipの追加価値は、現時点では成立していません。M0は不合格としてM1・M2へ進めません。** 困りごとの存在を否定する判断ではなく、現行の形式検知・端末通知が用途に合わないという判断です。
一般パスワードの形式検知を増やして公開を急ぐことは推奨しません。防御ツールとしての全国配布の根拠もありません。

次の判断材料は、漏洩不安が「保存サービス側」「コピーの残留」「誤貼付」のどこにあるかと、ターミナルの実際の入力種類です。既存手段を採用できない具体的な理由が残るなら、その1場面を再設計候補として評価します。新機能や自動上書きへの着手は別判断です。
ユーザーが対象を明示して秘密をコピーする手動モードは形式推測を避ける仮説にはなりますが、操作負担や他のコピーとの競合が残り、解決済みとも実装すべきとも判断していません。

本机上評価は5作業日の実利用観察を代替しません。ただし、用途と検知対象の不一致は、追加実機試験を待たずに公開準備を止める根拠になります。
