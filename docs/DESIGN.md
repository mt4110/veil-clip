## 現在の実装範囲

`src/detector.rs`と`src/engine.rs`を`src/lib.rs`から公開するコアライブラリです。
本文を持つ対象は非公開型とし、入力のDebug表示は伏せます。操作要求とイベントは本文を持ちません。
時刻は呼出側から`Instant`として渡し、時刻の逆行と誤った操作順序を拒否します。
読取の開始前ではなく、読取が完了して検知できる時点の時刻を渡します。
`observe`→`ReadAgain`→新しい読取結果を渡す`confirm`→必要なら`report_write`という順序です。
書込要求を発行した時点では成功扱いにせず、失敗報告では停止して`ExitFailure`を返します。
実際のOS操作・プロセス終了は呼出側の責務です。現在のCLIは`Mode::Observe`を固定し、読取だけのバックエンドを使います。予期しない書込要求が返れば実行せず停止します。

通常のポーリング、起動時入力、期限境界、内容変更、最終確認の失敗、UTF-8のサイズ境界、停止、モック書込を自動検証します。
CLIの引数拒否・日英文言・ログ抑制・読取復帰・スケジュール・停止フラグと待機解除をモックで検証します。ヘルプ・バージョン・不正引数のプロセス試験はOS接続前に終了します。
合成ダミーの実際の読取・期限通知・取り消し・Ctrl+CによるSIGINT終了をmacOSで確認しました。スリープ復帰、実機のアクセス障害・競合と性能は未検証です。排他コンポーネントは実装・検証済みですが、監視CLIや将来の上書きモードには接続していません。

## 3. 操作と既定値

macOSで監視CLIを実行できます。基本動作の実機検証は下記の範囲で実施済みです。`--apply`は将来案であり、現在は初期化前に拒否します。

```text
veil-clip                     # 監視のみ。読み取りはするが書き込まない
veil-clip --apply             # 現在は拒否。将来の上書き案
veil-clip --lang en           # 英語のヘルプ・ログ
veil-clip --help
veil-clip --version
```

- ポーリング500ms、TTL5秒は最初の固定値です。設定ファイルや自由な時間指定は後続判断とします。
- TTLはコピー時刻ではなく、検知した時刻から数えます。起動前の滞留時間は分かりません。
- 標準入力、引数、環境変数で秘密情報を渡す診断機能は設けません。
- 将来の上書き案では、テキスト全体を固定文字列`[REDACTED BY VEIL-CLIP]`に置換します。部分置換・復元機能は設けません。
- 起動時に監視モード、対象範囲、TTL、履歴と時間の限界を日本語または英語で表示します。
- 監視モードのログも種類とイベントのみです。同一内容の周期的な再検知はあり得るため、本文を保持しない種別・時刻ベースの出力抑制を使います。
- 監視モードの期限到達は「上書き予定時刻に到達。監視モードのため未変更」と表現します。
- Ctrl+Cで停止します。停止時に書き込まず、既に行った置換も元に戻しません。
- 将来の上書きモードの複数起動は避けます。実装ではOSが解放するユーザー単位の排他ロックを必須とし、取得できなければ起動を拒否します。単なるPIDファイルは排他の証拠にしません。

現在のCLIは標準エラーへ出力し、同一イベントを30秒間抑制します。取り消し時は検知・期限通知の抑制を解除し、新しい対象を通知します。読取復帰は別の静的通知を出し、読取障害の対象外・取り消し通知の抑制を解除します。本文やハッシュで履歴を管理しません。
`ContentNotAvailable`は空と非テキストを区別できないため、通常の対象外入力にします。占有・非対応・その他の障害は静的分類だけを通知します。
Ctrl+Cのハンドラは停止フラグを設定して待機へ通知します。OS読取中はその完了まで停止が遅れる可能性があります。

## 4. 状態と期限処理

Clipboardへの操作は一つのスレッドに集約します。asyncランタイムや秘密情報ごとのスレッドは不要です。
`Instant`で期限を表し、OS操作の完了後に次のポーリングまたは期限まで休眠します。
OSの読取・書込は遅延し得るので、500msや5秒を厳密な上限として保証しません。

```text
Idle --対象テキスト検知--> Pending(対象全文, 種類, deadline)
Pending --同じ全文・期限前--> Pending(期限は延長しない)
Pending --別のテキスト--> 古い対象を解放し、新しい内容を検知
Pending --非テキスト / 空 / 読取失敗 / サイズ超過--> 対象を解放してIdle
Pending --期限到達--> 再読取・完全一致確認
  異なる / 失敗: 書き込まない。読めた新しい内容は新規入力として検知
  同じ + 監視モード: 未変更イベントを出し、対象を解放
  同じ + 上書きモード: 一度だけset_textを試み、対象を解放
  書込成功: 現在のクリップボードへの置換成功を報告しIdle
  書込失敗: 失敗を報告して非ゼロ終了。古い対象のまま再試行しない
```

新しい秘密情報を観測したら、古い対象の期限を引き継がず、その検知時刻から新しいTTLを開始します。
同じテキストを再コピーしても、`arboard`のテキストだけでは区別できずTTLは延長しません。
観測間のA→B→Aも見逃します。書式だけの変更や複数形式の同時格納も完全には観測できません。
上書きはテキスト以外の付随形式にも影響し得ます。

`arboard`は条件付きの原子的な置換を公開していません。最終読取と`set_text`の間に競合が残ります。
排他ロックで防げるのは本ツール同士の競合だけです。他アプリのコピーは防げません。
他のコピーを絶対に守ることが必要なら、この上書き方式を採用せず、監視のみかOS別方式を再設計します。

初期化失敗は本文を含めず非ゼロ終了します。
読取エラーは種類を分け、対象を取り消します。空・非テキストは通常入力として扱い、アクセス障害は種類だけ警告します。
繰り返す障害はログを時間で抑制し、読取を500ms間隔で継続します。復旧後は新しい検知時刻でTTLを始めます。
この取り消しは、確認できない内容への書込を避ける判断です。その分、障害中や復旧後は対象が当初のTTLより長く残り得ます。
スリープ復帰後も最初に再読取します。停止・スリープ中の消去は保証しません。

## 5. 検知ルール

検知は形式のヒューリスティックです。認証先への照会や鍵の有効性判定は行いません。

| ルールID | 初期対象 | 注意 |
| --- | --- | --- |
| aws-access-key-id | 大文字のAKIAまたはASIA + 16文字のASCII英大文字・数字 | IDのみ。秘密アクセスキー単体・セッショントークンは対象外 |
| private-key-header | 下記の完全一致ヘッダー | サンプル文や解説も検知し得る。鍵本文の妥当性は調べない |

AWS候補は`(?:AKIA|ASIA)[A-Z0-9]{16}`で見つけます。
`regex`はlook-aroundを使えないため、候補の前後がASCII英数字または`_`なら除外する境界確認をRust側で行います。
長い識別子の一部分を誤って消さないための保守的な条件で、全形式を網羅する主張ではありません。
複数候補があれば、境界不一致の候補だけを除外して検索を続けます。

対象ヘッダーは次の5つです。Ed25519等のアルゴリズム名ではなく、保存形式のヘッダーを検知します。

```text
-----BEGIN PRIVATE KEY-----
-----BEGIN ENCRYPTED PRIVATE KEY-----
-----BEGIN RSA PRIVATE KEY-----
-----BEGIN EC PRIVATE KEY-----
-----BEGIN OPENSSH PRIVATE KEY-----
```

一般のパスワード、任意APIトークン、JWT、公開鍵、証明書、未列挙の鍵形式は対象外です。
検知ルールを増やす前に、誤検知による通常コピーの置換と実際の不足を確認します。

## 6. データと資源

`get_text`が返すUTF-8テキストは読み取りのため一時的にメモリへ入ります。
通常文は保持しません。Pendingの対象全文を1つだけ保持し、ログにも永続化にも渡しません。
完全一致確認のため、期限時に対象と現在の内容が一時的に並存します。不要なcloneを避けます。

検知対象の上限は初期案で1MiB（UTF-8バイト長）です。これは運用上の制限で、性能測定由来ではありません。
超過したら対象を取り消し、書き込まず、値を出さない警告を行います。
`get_text`の割当後にしか確認できないため、プロセス全体のメモリ上限や巨大入力への防御にはなりません。

Pendingは期限、変更、失敗、停止で解放します。OS呼出中は解放が遅れる場合があります。
通常のString解放ではメモリのゼロ化を保証できません。swap、core dump、OS・ライブラリ内部のコピーも制御しません。
メモリゼロ化をリリース要件にする場合は、追加依存と所有経路を別途確認します。

ログはモード・ルールID・状態・静的なエラー分類だけとします。
本文、抜粋、ハッシュ、呼出元アプリ、コピー履歴は記録しません。生のDebug出力をしません。
ネットワーク、テレメトリー、永続データ、鍵の検証APIは設けません。

## 7. 構造・依存・環境

`src/detector.rs`がルール、`src/engine.rs`が状態遷移、`src/lib.rs`が公開境界です。
`src/cli.rs`が引数と文言、`src/monitor.rs`が読取スケジュールと通知、`src/clipboard.rs`がmacOSの読取専用接続、`src/main.rs`が起動・停止です。
エンジンは時刻と読取結果を入力にし、次の動作を返します。
モックと制御した時刻で検証し、本物のクリップボードをテストで触りません。

- macOSだけに`arboard` 3.6.1（`default-features = false`）と`ctrlc` 3.5.2を追加しました。画像機能は使いません。`ctrlc`のtermination featureは無効で、Ctrl+Cだけを扱います。
- `regex` 1.13.1を採用し、`std`と`perf`だけを有効にしました。Detector構築時に一度コンパイルします。
- AWSは正規表現とASCII境界検査、秘密鍵ヘッダーは固定文字列の検索です。
- Cargo.toml・Cargo.lockを作成済みです。推移依存を含む49外部クレートのライセンス表記を確認しました。ロックには他OS向けの解決結果も含みますが、対応OSの証拠ではありません。
- arboardはMIT OR Apache-2.0、ctrlcはMIT/Apache-2.0です。安全なパス操作にはrustix 1.1.5（std・fs・processのみ）を追加しました。ロックは標準File APIです。rustixのライセンス表記はApache-2.0 WITH LLVM-exception OR Apache-2.0 OR MITで、Cargo.lockの監査に警告はありませんでした。
- miseで開発Rustを1.98.1へ固定し、実装時のCargo操作もmise経由で実行します。MSRVは未宣言です。
- Cargo.lockはコミット対象です。fmt・clippy・コア・CLI試験・ビルド・依存監査のmiseタスクとCI設定を用意しました。
- cargo-audit 0.22.2を開発ツールとしてmiseで固定します。監査は公開RustSecデータベースへのアクセスを伴います。監査合格だけで安全と判断しません。
- CIはUbuntu 24.04とmacOS 15で自動検査し、Ubuntuで依存監査する設定です。GitHub Actionsの実行は未確認で、Linuxのクリップボード対応を意味しません。

## 8. 検証と終了条件

実装開始後、次の順に進めます。実機の読取・上書き・自動起動・公開は、それぞれ承認された範囲でのみ行います。

1. OSに触れない検知・状態遷移の実装と単体検証。
2. 合成ダミーのみを使うmacOSの監視モード検証。
3. 競合の限界を受け入れた場合だけ、ダミーによる上書きモードの検証。
4. 実際の作業で必要性と不便を評価し、継続か終了を判断。
5. 非公開報告窓口・文書・CI・対象OSの証拠を整えてからリリース判断。

| 必須の検証 | 期待する結果 |
| --- | --- |
| 起動時に対象、通常文、空、画像 | 対象だけ期限を開始。他は変更しない |
| TTL中に対象A→通常文B | Aの期限を取り消し、Bに書き込まない |
| TTL中に対象A→対象C | Cの検知時刻から新期限 |
| 同じ対象の連続読取 | 期限を延長しない |
| 期限直前と期限一致 | 早期上書きなし。期限以降のみ最終確認 |
| 最終確認で別内容・読取障害 | 書き込まない。古い対象を解放 |
| 監視モードの期限到達 | 書込呼出がゼロ |
| 書込障害 | 成功ログを出さず非ゼロ終了、再試行なし |
| 再起動・停止・スリープ復帰 | 再読取し、停止時の無条件書込なし |
| 境界、短すぎるID、長いID、各ヘッダー、公開鍵 | 定義済み形式だけ検知 |
| 上限直前・一致・超過と日本語本文 | バイト長で判断。本文をログに出さない |
| 上書きモードの2つ目の起動 | 排他取得失敗で読取・書込を開始しない |

TOCTOU競合・観測間の変化・履歴消去は単体試験で解消したと扱いません。
性能はOS、Rust・依存版、入力サイズ、モード、測定時間、CPU/RSS、観測から置換までの遅延を記録します。
改善率や「負荷ほぼゼロ」は未測定のまま表記しません。

終了条件は、上記の安全条件と実機確認が揃い、コピーから貼り付けまでの実作業で使う理由が示せることです。
通常コピーの損失が観測された場合は上書きモードを止めて原因を調べます。

## 10. 実装前の調整判断（2026-10-06）

この節は現行コードとの照合と実装方針です。排他コンポーネントと検証用の例を実装しました。ゼロ化と上書きモードは未実装です。

### ユーザー単位の排他

第一候補は追加クレートを使わない`std::fs::File::try_lock`です。Rust標準では1.89.0から利用でき、固定した1.98.1でもAPIのコンパイルを確認しました。非ブロッキング取得と、全関連ハンドルの閉鎖による解放を提供します。別プロセスの正常終了・SIGKILL後に、同じinodeのファイルで再取得を確認しました。[Rust File API](https://doc.rust-lang.org/std/fs/struct.File.html#method.try_lock)

| 方式 | 判断 |
| --- | --- |
| 標準Fileの排他ロック | 第一候補。追加依存を避け、所有するFileを起動中保持する |
| fd-lock 4.0.4 | RAIIのガードが必要、または将来のMSRVで標準APIが使えない場合の候補 |
| fs2 0.4.3 | ファイルロックの候補。今回必要な機能は標準APIと重なるため採用を保留 |
| POSIX名前付きセマフォ | 今回は採用しない。終了時の参照解放を、獲得済みカウントの復元と同一視しない |

fd-lockとfs2は協調するプロセス間のロックです。悪意ある同一ユーザーのプロセスへの防御にはなりません。[fd-lock](https://docs.rs/fd-lock/4.0.4/fd_lock/)、[fs2](https://docs.rs/fs2/latest/fs2/trait.FileExt.html)
名前付きセマフォは`sem_wait`で獲得し`sem_post`で戻します。`sem_close`は参照解放です。このAPIの区別から、クラッシュでカウントが自動復元される前提にはしません。[sem_wait](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/sem_wait.2.html)、[sem_post](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/sem_post.2.html)、[sem_close](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/sem_close.2.html)

将来の上書き実装では、以下を受け入れ条件とします。

- バージョン・作業ディレクトリ・PIDに依存しない、ユーザーごとの共通パスを使う。実装は`/usr/bin/getconf DARWIN_USER_DIR`が返すOS管理のユーザー保存先に`veil-clip/apply.lock`を置く。getconfは環境を消して実行し、HOME・TMPDIR・作業ディレクトリ・バージョン・PIDに依存しない。実UIDと実効UIDが異なる場合とroot実行は拒否する。
- 専用ディレクトリ0700、通常ファイル0600を基本に、所有者・種類・権限を確認する。既存の不正なパス、シンボリックリンクや差し替え競合への対処を決め、確認できなければ起動を拒否する。ネットワークFSへ暗黙に退避しない。
- ファイルを切り詰めずに開き、排他取得後にクリップボードを初期化する。競合とその他の取得失敗は静的な別エラーで非ゼロ終了し、待たない。
- ハンドルを監視終了まで保持し、cloneや子プロセスへの継承を避ける。ロックファイルには本文・ハッシュ・PIDを書かず、通常終了時にも削除しない。削除・再作成すると別のファイルをロックして二重起動できるため、存在を「残留ロック」と判定しない。
- 別プロセスによる同時起動、正常終了、異常終了・強制終了後の再取得、既存ファイル、不正権限・リンク、取得失敗時のクリップボード呼出ゼロを検証する。

監視専用CLIの複数起動を禁止する必要は現時点ではありません。排他は本ツール同士を調整するもので、他アプリのコピーとの競合を解消しません。

実装: `src/instance_lock.rs`。OS管理の親は0755も許容し、開いた各祖先をrootまたは現在のユーザーが所有し、グループ・他ユーザーが書き込めないことを確認します。最終の親は現在のユーザーの所有を必須にします。専用ディレクトリは0700、通常のロックファイルは0600・リンク数1を必須にします。既存の権限を自動修正せず、不一致なら拒否します。
macOSの既知の`/var`だけを`/private/var`に置き換え、以後は`openat`・NOFOLLOW・DIRECTORYで各要素を開きます。作成・確認は保持したディレクトリハンドルを基準に行い、取得後もディレクトリとファイルのパス上のinode一致を確認します。CLOEXECでexecへの継承を防ぎ、非通常ファイルでブロックしないようNONBLOCKで開きます。プローブはforkせず、所有ハンドルを公開しません。

`examples/lock-check.rs`はクリップボードを含まない確認用です。`mise exec -- cargo run --locked --example lock-check`で取得し、Enterまたは入力終端まで保持します。別のターミナルで同じ例を実行すると静的エラーで終了コード1になります。通常終了・強制終了後も空のロックファイルは残ります。
`tests/instance_lock.rs`はtarget内の専用fixtureと独立した子プロセスを使います。競合、正常終了・SIGKILL後の再取得、同じinodeの保持、既存内容の非切り詰め、リンク・ハードリンク・権限・非通常ファイルの拒否を確認しました。所有者不一致とinode不一致はメタデータ判定の試験です。実際の別UIDでの起動は未検証です。fixtureは削除せずtarget内に残します。
2026-10-06、macOS 27.0.1 / arm64で実保存先のプローブも確認しました。HOME・TMPDIRを存在しない値へ変更し、別の作業ディレクトリから起動しても同じロックで競合し、正常終了・SIGKILL後に再取得できました。今回クリップボード操作はありません。
限界: POSIXの所有者・modeを検査しますが、macOSの追加ACLやネットワークマウントの判定は未実装です。OSが返す標準のローカル保存先を対象とし、代替パスへの退避はしません。管理者・悪意ある同一UIDのパス差し替えや、取得後のパス削除を防ぐ保証はありません。上書きモード接続前には実運用のACL・保存先寿命も確認します。現在の監視CLIにこのロックは接続していません。

### AWS候補の境界と構造化テキスト

現行の定義を維持します。候補の直前・直後が存在し、それがASCII英数字または`_`なら除外します。それ以外は境界として許容します。許可文字を列挙する方式ではありません。

| 入力の例（IDは合成ダミー） | 現行定義での期待 |
| --- | --- |
| `AKIA0000000000000000` | 文字列の先頭・末尾で検知 |
| `{"access_key_id":"AKIA0000000000000000"}` | クォートで区切られたJSON値を検知 |
| `?access_key_id=AKIA0000000000000000&next=1` | `=`・`&`で区切られたURL値を検知 |
| `/AKIA0000000000000000/`、空白・改行・タブ・クォート・括弧・句読点で囲む | 検知 |
| `prefixAKIA0000000000000000`、`AKIA0000000000000000_` | ASCII識別子の一部として除外 |
| `日本語AKIA0000000000000000日本語` | 非ASCIIを境界として検知。Unicode識別子の検証ではない |

JSONやURLを構文解析せず、コピーされたテキストをそのまま検索します。URLのパーセントエンコードやJSONのUnicodeエスケープで分断されたIDは復号しません。説明文やサンプルのIDも検知します。URL・JSON内の一部分だけを消す機能はなく、将来の上書き案ではテキスト全体が置換対象です。
AKIA・ASIAの両方について、JSON値・URLパラメータ・パス・フラグメント、ASCII全128文字の境界、非ASCII境界（日本語、全角文字、結合文字、絵文字等）を合成ダミーで試験しました。ASCII英数字・`_`は左右それぞれと両側で除外し、それ以外のASCIIは左右それぞれと両側で検知することを確認しました。IDの各文字を1文字ずつJSONのUnicodeエスケープまたはURLのパーセントエンコードへ置き換えた入力も、復号して検知しないことを確認しました。検知コードの変更は不要でした。

「復号しない」は、エンコードを含む入力全体を対象外にする意味ではありません。たとえば`%20AKIA0000000000000000`は直前の`0`により除外しますが、`AKIA0000000000000000%41`は直後の`%`を境界として検知します。JSONでもID直後の`\u0041`は生のバックスラッシュを境界として扱います。これらの生テキストの判定も試験しました。構文解析・復号した値の妥当性は判定しません。

### 本文・ハッシュを保存しないログ抑制

現行Engineは、同じ全文がPending中に読まれてもDetectedを再発行しません。一方、ルールIDと時刻だけでは同じルールに一致する別の本文を区別できないため、取消・再確認のための対象全文は引き続き必要です。ログ用の保持と、期限管理の保持は別の責務です。

監視の期限到達後は全文を解放してIdleへ戻ります。その後の同一本文は再検知します。EventLoggerは本文・ハッシュを持たず、イベントの種類と最終出力時刻で30秒間の抑制を行います。Detectedにはルールの組み合わせも含みます。対象の取り消しで検知・期限通知の抑制を解除します。

この方式を維持し、保証は「Pending中は重複検知イベントを出さず、期限後の反復通知は時間で抑制する」とします。「同一本文を一度だけ通知する」とは保証しません。期限直後の別の対象が同じルールなら、取り消しを観測できず通知が抑制される場合もあります。通知がないことを、検知対象がない証拠にしません。
一度だけの通知が必要になった場合は、期限後も全文を保持する案と、OS固有の変更世代を使う案の費用・保持時間を比較します。ルールIDだけの同一判定や、要件を迂回するハッシュ保存は採用しません。

### メモリゼロ化の導入条件

現在の非公開Targetと伏せ字Debugを維持します。将来要件のためだけに、効果のない`ClipboardSecret(String)`を先行追加しません。アプリが所有するバッファのゼロ化をリリース要件とする時点で、独自型とゼロ化を一緒に導入します。
候補は最小構成の`zeroize::Zeroizing<String>`を包む型、または明示的な本文参照が必要な`secrecy::SecretString`です。zeroize 1.9.0はStringのバッファ容量全体をゼロ化しますが、再割当で過去に作られたコピーは保証範囲外です。secrecy 0.10.3は明示的な参照とDebug漏洩防止を提供します。[zeroize](https://docs.rs/zeroize/1.9.0/zeroize/)、[secrecy](https://docs.rs/secrecy/0.10.3/secrecy/)

導入時は`get_text`の戻り値をコピーせず直ちに包み、ReadOutcome→Input→Target→最終確認の全所有経路を確認します。通常文・空・サイズ超過・取消・停止・エラー経路と、確認用の一時バッファも対象です。Debugは伏せ字、Clone・Display・シリアライズや所有Stringの取り出しを原則提供せず、検知・比較は借用します。Pendingだけを包んでも、他の読取バッファのゼロ化にはなりません。
Dropが実行されないabort・強制終了、OS/arboard内部のコピー、再割当の旧バッファ、swap・core dump・他アプリの内容は消去保証の対象外です。ゼロ化の試験を、解放済みメモリへの不正なアクセスやOS全体の消去の証明にしません。依存の保守・ライセンス・脆弱性とfeatureは導入時に再確認します。
