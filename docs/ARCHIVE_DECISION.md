# アーカイブの判断記録

[English](ARCHIVE_DECISION.en.md)

決定日：2026-10-07。状態：開発・公開準備を凍結。ユーザーの判断によりGitHubリポジトリを読み取り専用としてアーカイブします。コード・試験・検討資料は保持します。

## 凍結した理由

確認した主な利用場面は、付箋やロックしたメモから一般的なパスワードをコピーし、ターミナルやブラウザへ貼り付ける操作でした。
現行の検知対象はAWSアクセスキーIDの形式と定義済み秘密鍵ヘッダーです。一般的なパスワードを確実に識別せず、CLIは通知のみで消去・貼り付け阻止を行いません。この用途に対する追加価値が成立しませんでした。

ユーザーから、追加開発を正当化する別の利用場面も思いつかないとの判断があり、開発継続ではなく凍結を選びました。既に作ったコードの量やセキュリティ全体の需要を、継続の根拠にしません。

保存内容の保護、コピー後の残留、誤貼り付けは異なる問題です。既存のパスワード管理・自動入力等には候補がありますが、ユーザーの全環境で代替できることを実証したわけではありません。詳細は[パスワード用途の机上評価](PASSWORD_USE_CASE.md)を参照してください。

## 確認したことと限界

- 検知・TTLコア、macOS監視専用CLI、排他ロック単体と試験を保持します。ロックはCLIに未接続です。
- 限定した合成ダミー実機確認と、PR #1のUbuntu・macOS CI成功・マージの記録があります。
- パスワード用途の評価はユーザー申告、コード、公式資料による机上評価です。実際の秘密を取得せず、事故の再現は行っていません。
- 5作業日の利用観察は未完了です。完成済みの観察結果や、全利用者に不要という証明として扱いません。
- 上書き・自動起動・GUI・監査・ペースト監視は未実装です。読み取りと書き込みを別操作にする上書き方式には、新しいコピーを失う競合が残ります。

結論は「今回確認した自己利用では、現行方式の追加開発・公開を正当化する必要性を確認できず、別の用途も得られなかった」です。

## 凍結中の扱い

新機能、公開準備、5作業日の追加観察、日々の進行は停止します。定期実行は設定していません。サポート対象のリリースやセキュリティ更新の提供はありません。既存コードを保護済みの製品として利用しないでください。
リポジトリ内の計画や試験手順は履歴資料です。タスク表に未完了事項があっても、現在の実行指示ではありません。
アーカイブはGitHubの編集を止める操作で、ローカルのファイルや手動起動したプロセスを停止・削除する操作ではありません。

## 再開条件

1. コピー元・入力先・具体的な問題・必要な振る舞いを示す利用場面が見つかる。
2. その場面で確認した既存手段では不足する理由が、未使用や印象だけでなく説明できる。
3. データ最小化、誤検知、他のコピーの保全を含む安全条件と検証方法を決められる。
4. 主力プロダクトへの影響を含む小さな作業範囲と終了条件を決め、ユーザーが再開を承認する。

思いつきだけで自動再開しません。再開時はGitHubのアーカイブ解除を明示承認の下で行い、ツールチェーン・依存監査・CI・実機条件・報告窓口を再確認します。保存された過去の合格を、将来の動作や安全の証拠にしません。
