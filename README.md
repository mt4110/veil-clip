[English](README.en.md)

クリップボードに残った機密情報らしいテキストを検知し、ターミナルへ通知するmacOS向けローカルCLIです。

**macOS向けの監視専用CLIと、検知・TTLコアを実装しました。上書きと自動起動は未実装です。**
[公開準備計画](docs/RELEASE_PLAN.md)と[利用場面確認の様式](docs/USE_CASE_VALIDATION.md)を履歴として保持しています。パスワード用途の机上評価後、追加開発を正当化する別の用途も得られず凍結しました。5作業日の観察は未完了です。
コアはOS操作を行いません。CLIは`arboard`で読み取り、検知と期限到達を通知します。macOSで合成ダミーによる読み取り・期限通知・取り消し・Ctrl+C終了を確認しました。

## 実装済みのコア

- AWSのAKIA／ASIA形式と、5種類の秘密鍵ヘッダーを検知します。
- 内容が変わったら古い期限を取り消し、新しい対象には新しい5秒のTTLを開始します。
- 期限到達時は再読取を要求し、確認結果が全文一致した場合だけ置換を要求します。
- 監視モードでは置換を要求しません。書込失敗の報告を受けたら停止し、再試行しません。
- 通常文を保持せず、対象全文は最大1つです。UTF-8バイト長で1MiBを超える入力は対象外です。
- 操作要求とイベントに本文を含めず、入力のDebug表示も本文を伏せます。

コアの操作要求はOSへの書き込みそのものではありません。
検知と状態遷移を合成ダミーとメモリ上のモックで検証しています。macOSで限定した実機確認も行いました。スリープ復帰・障害時の実機動作・性能・製品価値は未検証です。

## 目的

開発中にコピーした認証情報を、そのままクリップボードへ放置する事故を減らします。
パスワード管理アプリの自動消去で十分な場合は、それを使う方が管理するソフトウェアを増やさずに済みます。
本プロジェクトは、それ以外のコピー元にも必要かを小さく検証します。

## 現在のCLIの動作

- 最初の実機検証対象はmacOSです。Windows・Linux・WSL2は未検証です。
- ユーザーが起動するフォアグラウンド常駐CLIとします。
- テキストを500ms間隔で読み取り、起動時の内容も検知対象にします。
- AWSアクセスキーIDと、定義済みの秘密鍵ヘッダーを検知します。
- 監視モードのみです。検知から5秒後に再確認し、未変更を通知します。待機中も監視を続けます。
- `--apply`は初期化前に拒否します。将来の上書き機能は別途判断します。
- 内容、抜粋、内容のハッシュをログやディスクへ保存しません。アプリからの外部送信は設けません。
- ヘルプ・ログ・文書は日本語を標準にし、英語も用意します。

ログは標準エラーへ出力します。同じイベントは30秒間抑制し、対象の取り消しや読取復帰時に関連する抑制を解除します。コピー履歴を網羅するログではありません。
Ctrl+Cで停止します。待機は通知で解除しますが、OS読取が停止している間の即時終了は保証しません。

```sh
# クリップボードへアクセスしないコマンド
mise exec -- cargo run --locked -- --help
mise exec -- cargo run --locked -- --lang en --help
mise exec -- cargo run --locked -- --version

# macOSで監視を開始する。現在のクリップボードを読み取ります。
mise exec -- cargo run --locked --
# 英語のログで監視する場合
mise exec -- cargo run --locked -- --lang en
```

2026-10-06にmacOS 27.0.1 / arm64で監視コマンドの基本動作を確認しました。詳細は[設計の実機検証記録](docs/DESIGN.md#macos監視cliの実機検証2026-10-06)を参照してください。手動検証には合成ダミーを使ってください。

## 保護の限界

現在のCLIは通知だけで、機密情報を消しません。将来の上書き機能でも対象は、その時点の通常のクリップボードです。
履歴、同期済みデータ、既に他アプリが読み取った内容、貼り付け先、元ファイルは消せません。
検知漏れ・誤検知もあります。AWSアクセスキーIDだけでは秘密アクセスキーを検知できません。

`arboard`による読み取りと書き込みは別操作です。
直前に再確認しても、その間にコピーされた新しい内容を上書きする競合は完全には防げません。
「完全消去」「漏洩防止」「5秒以内の保護」を保証しません。
詳しくは[設計](docs/DESIGN.md)と[セキュリティ方針](SECURITY.md)を参照してください。

## 開発環境

[mise](https://mise.jdx.dev/)でRustの開発バージョンを管理します。
Rust 1.98.1を固定しています。対応する最小Rustバージョンの宣言ではありません。

```sh
# 設定を読んでから、このリポジトリの設定を信頼する
mise trust
# 未導入の開発ツールがある場合に導入する
mise install
mise run toolchain
mise run check
mise run audit
```

ツール導入は各配布元へのネットワークアクセスを伴います。
`check`は文書、整形、clippy、コア・CLIテスト、ビルドを順番に実行します。
`audit`はmiseで固定したcargo-audit 0.22.2を使い、RustSecの公開データベースとCargo.lockを照合します。
監査にはネットワークアクセスが必要で、合格だけで安全を保証するものではありません。
Cargo.lockを管理対象にし、Cargo操作はmise経由で行います。MSRVは未宣言です。

同じ検査を実行する[GitHub Actions設定](.github/workflows/ci.yml)もあります。
ローカルでの成功と、リモートCIの成功は別に確認します。2026-10-07にPR #1のUbuntu・macOS CI成功とマージを確認しました。
